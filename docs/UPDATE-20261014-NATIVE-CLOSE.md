## 已确认的问题与边界

旧版可能留下 `pending` 存在、延后剩余为 0 的健身提醒。`FitnessEngine::restore` 原先无条件设置 `collapsed=true`，导致恢复后即使后台线程持续计入活动、输入源健康且未锁定，仍然不会创建提醒窗口。

隔离原生基线在 149 次后台 tick、149000 毫秒模拟时间后仍未出现窗口；同一个 pending ID 保留，活动累计持续增长，延后为 0，主窗口一直最小化。证据：`baseline-fitness-cold-minimized-20261014-180436-853032/report.json`。

修复只重新启用已到期旧提醒的显示调度，实际弹出仍受启用状态、输入源、系统监测和锁定状态控制。保存格式、运动内容、pending ID、累计活动、历史记录均不变，不伪造“稍后”“完成”或“跳过”记录。

这确认了一个旧记录恢复缺口，但不能据此断言它是用户本次“新弹窗点击标题栏 × 后消失”的唯一原因。修改前，健身提醒在主窗口最小化时的 `SC_CLOSE` 和 `WM_CLOSE` 两轮测试已经能按现有延后设置自动重弹。后台计时在 Rust 原生线程，主窗口隐藏不会主动停止该线程。
