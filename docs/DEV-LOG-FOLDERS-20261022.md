## 用户可见改动

- PDF 图片忽略编辑器里的缩放，按原图自然尺寸排版；超过 A4 可用宽度或高度时等比例缩小，不将小图额外放大。标题、未保存正文、中文格式、原图资源和分页继续沿用本地导出流程。
- 项目行新增文件夹按钮，位于新建页面右侧；点击立即使用“新建文件夹”“新建文件夹 2”等默认名称创建，无需填写对话框。
- 文件夹是项目下一级分组，可单击整行展开/折叠，双击或右键“重命名”；Enter 保存、Esc/失焦取消，沿用输入法保护。
- 页面可拖到文件夹行加入该文件夹、拖到另一个文件夹移动，或拖回项目行回到根层；拖到页面前可调整顺序。文件夹可在同项目根层的文件夹和页面之间排序，目标位置有高亮。跨项目拖动不执行。
- 项目名称整行单击即可立即折叠/展开，双击继续改名并恢复原折叠状态，不切走正在编辑的页面；整行与箭头都不等待双击判定。详见 [响应修复记录](FIX-LOG-ROW-RESPONSE-20261022.md)。
- 项目数字只统计该项目全部活动页面，包含文件夹中的页面，不计文件夹。文件夹内可直接新建页面，新页面挂载并可编辑后自动定位光标。

文件夹创建和改名不保存当前草稿；移动和新建页面沿用原来页面整理/切换时的保存规则，关闭自动保存且存在草稿时会要求处理草稿。

## 数据与恢复

仓库 schema 从 v5 升级到 v6，沿用既有迁移流程：任何结构变更之前先做完整仓库备份，随后在事务中创建 `dev_log_folders` 和 `dev_log_page_folders`。原页面文档、资源字节和历史记录结构保持原样，现有页面默认位于项目根层。

文件夹名称、页面归属与顺序保存在仓库中，随完整仓库备份保留。文件夹移动采用版本检查和同项目校验；页面排序会更新其元数据版本，但不重写正文或增加内容历史。IPC 沿用开发日志窗口权限和编辑租约检查，其他窗口正在编辑受影响页面时拒绝修改。

项目进入回收站后保留文件夹归属，恢复项目会恢复原布局；永久删除项目时清理其文件夹和关联记录。本轮没有打开或改写真实用户仓库。用户下次打开新版时会自动完成受保护的 v5→v6 升级；旧版 EXE 不支持 v6 仓库，回退应使用升级前完整备份并保留升级后的数据。
