## 功能与使用

- 保存按钮右侧新增“导出 PDF”，输出当前页的标题和完整正文，包括尚未保存的草稿。
- 页面树的页面右键菜单及“…”菜单增加“导出为 PDF”。导出其他页时不切换页面，不保存或丢弃当前草稿；右击当前页同样使用草稿。
- 选择保存位置，默认文件名为页面标题；取消后不生成文件。导出时显示进度并暂时禁用编辑，错误明确提示。
- A4 竖向、白底、16 mm 页边距。保留中文、粗体、斜体、下划线、上下标、文字颜色、高亮、对齐、超链接、列表、待办状态、引用和代码。普通段落与长代码可跨页，标题尽量与后文保持在一起。
- 图片从仓库原始资源读取，包含尚未滚动到的图片；按原图尺寸排版，忽略编辑器缩放，超出纸面时等比例缩小到单页，整张图片与说明避免被拆开。PNG/JPEG/WebP/GIF 可导出，GIF 为静态画面。最新原图及文件夹验证见 [后续记录](DEV-LOG-FOLDERS-20261022.md)。
- 普通附件显示文件名和大小，不将文件正文合并或嵌入 PDF。

## 实现

沿用官方 MIT Tiptap Simple Editor。官方另行收费的 Conversion PDF 扩展需要认证并调用转换服务，本次没有接入。

`pdf.ts` 从验证后的日志 JSON 生成正文，不抓取编辑器 DOM，避免遗漏懒加载图片、混入行号和操作控件。`pdfExport.ts` 请求保存位置、读取资源并检查图片可解码。`dev_log_pdf.rs` 在临时目录创建独立 HTML，通过隐藏的 WebView2 原生 PrintToPdf 输出，再使用既有的路径保护和原子写入函数保存目标 PDF。临时视图禁止脚本、网络及额外页面导航，没有新增 IPC 权限。

导出不触发日志保存或编辑租约切换，不改写资源字节，不修改数据库结构。现有定时自动保存规则继续适用；关闭自动保存即可验证纯未保存草稿的导出。导入附件本身仍沿用原来的资源与页面共同保存规则。

当前支持 Windows 桌面版。每页原图累计上限 64 MiB，渲染 HTML 上限 128 MiB；最终文件沿用既有导出写入器的 24 MiB 上限。资源缺失或解码失败时取消本次导出，避免静默输出缺图文件；仅在生成成功后替换已有目标文件。

## 用户验收

以下清单已由用户验收确认通过。

1. 打开原来的 `deliverables/Perfboard-0.1.0/perfboard.exe`，进入开发日志，确认“导出 PDF”位于保存右侧。
2. 关闭自动保存，输入一段中文但不要保存，导出并打开 PDF，确认新增文字和页面标题都在；页面应仍显示未保存。
3. 插入横图、长图和已有缩放尺寸的图片，使用长文/长代码导出多页，检查比例、完整性、分页和文字颜色。
4. 保留当前页未保存内容，右击另一页面导出，确认导出目标正确，当前页没有切走且草稿仍在；右击当前页应包含草稿。
5. 检查保存位置选择、取消和同名覆盖。
